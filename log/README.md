# Go 日志：从 slog 入门到企业应用

本目录的 `slog/main.go` 演示标准库 `log` 和 `log/slog`。下面是一份逐步实现的路线图，保留分析题和验收标准，供你自己编写代码。并非每个项目都需要所有能力。

## 运行当前示例

需要 Go 1.21 或以上版本。在仓库根目录运行：

```bash
go run ./log/slog/main.go
```

当前最低级别为 `Info`，因此最后的 `Debug` 不会输出。开头的 `slog.Info` 使用默认记录器，尚未使用后面创建的 JSON Handler。

## 第一阶段：统一基础行为

### 1. 日志级别和配置

- [ ] 用环境变量或配置项控制最低级别、输出格式和源码位置。
- [ ] 明确 Debug、Info、Warn、Error 的使用场景，拒绝无效配置或使用明确的默认值。
- 思考：生产环境默认开什么级别？临时排障怎样开启 Debug？
- 验收：分别设置 Debug、Info、Error，确认只有达到阈值的日志输出。

### 2. 统一初始化与依赖传递

- [ ] 集中创建 Logger，通过参数或结构体字段传给业务组件。
- [ ] 如需统一全局调用，研究 `slog.SetDefault`；兼容旧 `log.Logger` 时研究 `slog.NewLogLogger`。
- 思考：全局 Logger 和注入 `*slog.Logger` 各有什么取舍？测试时怎样替换输出？
- 验收：不同组件共享配置，并可独立增加模块字段。

### 3. 结构化字段规范

- [ ] 统一时间格式、时区、字段名和字段类型。
- [ ] 添加 `service`、`environment`、`version`、`instance_id`；用 `With` 添加公共字段。
- [ ] 事件消息保持稳定，将可变数据放进字段；耗时明确单位，例如 `duration_ms`。
- 思考：查询某次部署的全部错误，需要哪些字段？同名字段重复时如何处理？
- 验收：每行日志都是可解析的 JSON，相同事件的字段类型一致。

## 第二阶段：支撑请求排障

### 4. 请求关联与链路追踪

- [ ] 在 HTTP 入口生成或校验 `request_id`，通过请求上下文传递。
- [ ] 接入追踪后记录真实的 `trace_id` 和 `span_id`，保持跨服务关联。
- 思考：`InfoContext` 接收 context 后，会自动输出其中的值吗？答案是不会，需显式添加字段或编写 Handler 提取。
- 验收：同一请求经过多个函数仍能按 ID 查询，且并发请求字段不会串用。

### 5. HTTP 访问日志

- [ ] 使用中间件记录方法、路由模板、状态码、耗时及响应大小。
- [ ] 谨慎记录 URL 查询参数、请求头和请求体，明确跳过健康检查的策略。
- 思考：包装 `ResponseWriter` 后，如何保留 SSE 所需的 Flush 能力？客户端断开如何记录？
- 验收：成功、失败、流式请求和客户端取消都得到正确记录。

### 6. 错误与 panic

- [ ] 记录错误上下文及业务错误码，明确由哪一层负责记录，避免每层重复打印。
- [ ] 在合适边界恢复 panic、记录堆栈；其他 goroutine 需要自己的处理边界。
- 思考：业务错误和系统异常如何分级？哪些错误真的需要堆栈？
- 验收：一个失败事件可定位原因，不重复刷屏；日志记录不改变错误返回流程。

## 第三阶段：安全与输出可靠性

### 7. 脱敏与输出限制

- [ ] 对字段采用允许列表，禁止输出密码、Token、Cookie、密钥和完整证件信息。
- [ ] 研究 `ReplaceAttr`、`LogValuer` 或自定义 Handler；限制长字符串及大对象。
- 思考：密钥藏在错误字符串、嵌套对象或请求体中，按字段名脱敏能否覆盖？
- 验收：用虚构敏感数据验证所有输出渠道，包含嵌套和异常路径；不记录真实密钥进行测试。

### 8. 输出渠道与文件轮转（按部署方式选择）

- [ ] 容器环境优先评估标准输出加外部采集；需本地文件时配置大小、保留数量、保留天数和压缩。
- [ ] 需要多路输出时，区分“复制相同内容”和“分别过滤级别、设置格式”。
- 思考：谁负责轮转？目录无权限、磁盘满或某一路输出失败时怎么办？
- 验收：轮转后继续写入，旧文件按策略清理，多路输出失败不会悄悄丢失。

### 9. 写入失败与退出收尾

- [ ] 为 Writer/Handler 的写入失败设计独立诊断和计数，避免通过同一个失败 Logger 递归记录。
- [ ] 若使用缓冲或异步组件，在退出时限时排空并关闭资源。
- 思考：`slog.Info/Error` 不返回写入错误，在哪里观察失败？`os.Exit` 会跳过哪些收尾？
- 验收：模拟 Writer 失败可被发现；正常退出时完成收尾。标准 JSONHandler 本身不提供 Flush/Close，按底层组件能力处理。

## 第四阶段：根据规模扩展

### 10. 性能、采样与异步队列

- [ ] 先测量性能，再决定是否增加采样、限流或异步处理。
- [ ] 高频 Debug 避免提前执行昂贵计算；异步队列必须有容量和过载策略。
- 思考：队列满时阻塞、丢弃还是降级？哪些错误或审计事件不能采样？
- 验收：压力下内存有界，丢弃量可观察，关键事件策略明确；并发实现通过竞态检查。

### 11. 动态调级

- [ ] 研究 `slog.LevelVar`，实现并发安全的运行时级别调整。
- [ ] 如果提供管理接口，增加鉴权、变更记录和可选的自动恢复期限。
- 验收：不重启即可调级，未授权请求无法修改配置。

### 12. 集中采集、检索和告警

- [ ] 按现有基础设施选择采集器与日志平台，约定解析规则、重试、缓冲及保留策略。
- [ ] 设计错误突增、采集失败和日志丢弃告警，关联指标与追踪。
- 思考：高基数字段是否适合成为索引标签？采集平台离线多久仍能保留数据？
- 验收：可按服务、版本和请求 ID 检索，并通过模拟故障验证告警。

### 13. 审计日志与访问治理（有需求时）

- [ ] 将权限变更、配置变更等审计事件与普通诊断日志区分，记录操作者、动作、对象、结果。
- [ ] 明确读取权限、访问留痕、保留与删除规则；需要时使用独立存储和防篡改机制。
- 验收：普通业务账号不能随意读取或修改审计记录，敏感信息仍按规则处理。

## 每一步的验证方法

- 将实现拆成小步，每完成一项再勾选。
- 用 `bytes.Buffer` 捕获日志，通过 JSON 解析验证级别、字段、脱敏及格式，不只看终端输出。
- 用 `httptest` 验证中间件；用故障 Writer 验证失败路径；自定义 Handler 可使用 `testing/slogtest` 检查协议。
- 后续建立独立 Go 模块后，在模块目录运行 `go test ./...`、`go test -race ./...`、`go vet ./...`；性能敏感时再添加基准测试。
