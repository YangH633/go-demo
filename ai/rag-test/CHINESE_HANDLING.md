# 中文处理说明

## 向量化处理

### BGE-M3 模型对中文的支持

**重要**：BGE-M3 是一个**多语言嵌入模型**，原生支持中文，因此在向量化这一步，**不需要对中文做特殊处理**。

- BGE-M3 在训练时已经包含了大量中文语料
- 模型能够理解中文的语义，生成高质量的向量表示
- 不同语言在向量化这一步没有差别，模型会自动处理

### 向量化流程

```
中文文本 → BGE-M3 模型 → 1024维向量
```

**无需额外处理**：
- ✅ 不需要分词
- ✅ 不需要语言检测
- ✅ 不需要编码转换
- ✅ 直接输入原始文本即可

## 文本分块处理

虽然向量化不需要特殊处理，但**文本分块**可以针对中文进行优化。

### 当前实现

1. **字符级别处理**：
   - 使用 `[]rune` 而不是 `[]byte`，正确处理中文字符
   - 中文字符不会被错误分割

2. **智能分块**（已实现）：
   - 优先在句子边界分割（。！？；）
   - 避免在句子中间切断
   - 保持上下文完整性

3. **文本清理**：
   - 移除多余的空白字符
   - 规范化换行符
   - 保持文本可读性

### 分块策略对比

#### 旧方法（简单字符数分块）
```
问题：可能在句子中间切断
示例：
块1: "这是一个测试文档。这是第二"
块2: "句话。这是第三句话。"
```

#### 新方法（智能分块）
```
优势：在句子边界分割
示例：
块1: "这是一个测试文档。"
块2: "这是第二句话。这是第三句话。"
```

### 中文分块特点

1. **句子边界识别**：
   - 中文句号：。
   - 中文感叹号：！
   - 中文问号：？
   - 中文分号：；

2. **重叠策略**：
   - 默认重叠 50 个字符
   - 确保上下文连续性
   - 避免重要信息丢失

3. **最小块大小**：
   - 避免过小的块（可能丢失上下文）
   - 保持语义完整性

## 性能考虑

### 中文 vs 英文

| 特性 | 中文 | 英文 |
|------|------|------|
| 向量化 | 无需特殊处理 | 无需特殊处理 |
| 分块策略 | 按句子边界 | 按句子边界 |
| 字符编码 | UTF-8 (rune) | UTF-8 (byte) |
| 模型支持 | ✅ BGE-M3 原生支持 | ✅ BGE-M3 原生支持 |

### 为什么不需要特殊处理？

1. **BGE-M3 的设计**：
   - 专门为多语言设计
   - 在 100+ 种语言上训练
   - 包括大量中文语料

2. **向量空间特性**：
   - 语义相似的文本（无论语言）在向量空间中接近
   - 模型已经学会了跨语言的语义映射

3. **实际效果**：
   - 中文文档检索准确率高
   - 中英文混合查询也能正常工作

## 总结

1. **向量化**：BGE-M3 原生支持中文，无需特殊处理
2. **分块**：已优化为智能分块，在句子边界分割
3. **性能**：中文处理性能与英文相当
4. **使用**：直接使用中文文本，模型会自动处理

**结论**：不同语言在向量化这一步没有差别，BGE-M3 会自动处理。但文本分块可以针对中文优化，以提高检索质量。
